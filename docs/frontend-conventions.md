# Frontend Conventions

If a design system is not established yet in the project, go ahead and create one. Ask for directions when you want to establish a design system. The design system should fix a color palette, typography,
components to use, animation stuff etc. Use the frontend skills available to get help determining the design system. Save the design system on a doc that is easy to understand and concise on `docs/design-system.md`

- Prefer shadcn/ui: Use existing shadcn components whenever possible before creating custom UI. Extend or compose them rather than duplicating primitives. But of course, if the shadcn components are not suitable for a particular project, do not use them.
- Use frontend skills effectively: Leverage the available frontend skills—Impeccable, Emil Kowalski, and Remotion—when their expertise applies. Follow their guidance instead of reinventing established patterns.
- Award winning websites: Use award winning websites as a source of inspiration for colors and component designs
- Build polished UI: Prioritize clean hierarchy, spacing, typography, responsive behavior, accessibility, and thoughtful interaction states.
- Reuse before creating: Check existing components, patterns, and utilities before introducing new ones.
- Avoid generic UI: Don't settle for default-looking layouts. Use the skills and component system to produce intentional, cohesive interfaces.



If however, a design system exists already, 
- Keep it consistent: Follow the project's existing design language, tokens, components, and conventions.
